# Glossary

Purpose: define the did:btc terms that the README and code use. Sources: the pinned [did:btc draft](https://github.com/MicroStrategy/did-btc-spec/blob/2c45a85f90ba5f013654351a3b0224c7f523d153/index.html) and [BIP-136](https://github.com/bitcoin/bips/blob/master/bip-0136.mediawiki).

- **TxRef** — a BIP-136 transaction reference. It is a Bech32m string that encodes a block height, the transaction's index in that block and, in the extended form, an output index. Its first character encodes the network: `r`/`y` mainnet, `x`/`8` testnet, `q`/`p` regtest. A did:btc identifier is `did:btc:` (mainnet) or `did:btc:test:` followed by the TxRef of the transaction that created the DID. Code: `src/txref.ts`, `src/did.ts`.
- **OP_RETURN subject key** — output 0 of the creating transaction is an `OP_RETURN` whose payload is ASCII `did`, one byte of verification-relationship flags and a multicodec public key. That key is the DID subject's key: it authenticates and signs credentials as the DID. It is separate from the bitcoin wallet keys that control the DID. Code: `src/protocol.ts`.
- **DID-UTXO** — the draft's "DID UTXO": an unspent Pay-to-Taproot output that controls the DID. It is created as output 1 of the creating transaction. Spending it with an update envelope changes the DID document and moves control to output 0 of the spending transaction. Spending it with an `OP_RETURN` of ASCII `d` deactivates the DID. A DID with no DID-UTXO is final and cannot change. The resolver follows this chain of spends. Code: `src/resolver.ts`.
- **Version** — each document change or deactivation on the DID-UTXO spend chain. Version `0` is the creation. `--version-id` and `--version-time` select a past version. This numbering is a local convention; the draft does not define it.
- **Regtest DID** — the draft defines only the mainnet and `test:` prefixes. This project uses the `test:` prefix for regtest too, with BIP-136's regtest TxRef magic (first character `q` or `p`). This is a local extension, not part of the draft.
